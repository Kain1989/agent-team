# Mission Control portal (internals)

The local team-status portal: a FastAPI backend + a no-build static page, bound to
`127.0.0.1` only. It **reflects** the files the team writes (`team.json`, `BACKLOG.md`,
`log/`, per-dev `.standup/` progress files) and drives the **job queue** — the
submit → isolated-worktree → **approve** → commit loop.

For setup and the user-facing walkthrough see the top-level [`../../README.md`](../../README.md).
This doc is the architecture for someone working ON the portal.

## Run

```bash
./run_local.sh            # http://127.0.0.1:8770 (or $PORT); worker on, scheduler off
cd .. && .venv/bin/python -m pytest portal/tests -q     # the test suite
```

`run_local.sh` sources `team-mvp/.env`, prefers the `standup/.venv`, runs ONE uvicorn
worker (single-flight depends on a single instance/host), and sets `STANDUP_JOBWORKER=1`
(the queue worker) + `STANDUP_SCHEDULER=0` (no auto ticks).

## Layout

```
portal/
├── app.py            FastAPI app: read endpoints, the /api/actions queue, lifespan
│                     (starts the job worker + optional scheduler), CSRF + TrustedHost
├── api_jobs.py       the /api/jobs* router (create / list / get / cancel / approve / reject)
├── parsers/          the engine, all paths resolved relative to STANDUP_ROOT (paths.py)
│   ├── db.py         SQLite system-of-record for the job lifecycle (control/jobs.db)
│   ├── jobworker.py  the async worker: claims jobs, drives read-only + code-task paths
│   ├── agent_run.py  runs a job as a locked-down `claude -p` (the 4-layer gate)
│   ├── worktree.py   trusted git side: create worktree / stage+diff / commit / remove
│   ├── job_prompts.py  job types, target resolution (team.json), prompt builders
│   ├── team.py · backlog.py · log.py · devlog.py · comms.py   file parsers
│   ├── liveness.py · runs.py · scheduler.py   runner state + the optional tick daemon
│   └── actions.py    the run-standup / pm-review file-queue (control/requests → results)
└── static/           index.html + app.css + app.js (vanilla, no build step)
```

## HTTP surface

Read: `GET /api/status` (the whole Mission Control payload) · `/api/team` · `/api/log` ·
`/api/heartbeat` · `/api/runs` · `/api/blockers` · `/healthz`.

Jobs: `POST /api/jobs` (create) · `GET /api/jobs[?status=&type=]` · `GET /api/jobs/{id}` ·
`POST /api/jobs/{id}/{cancel|approve|reject}`. Mutating calls require an
`X-Requested-By: portal` header (or same-origin) — the CSRF guard.

Actions: `POST /api/actions/{run-standup|pm-review}` enqueue a tick request into
`control/requests/`; the optional runner drains it (see `control/drain.py`).

## Job lifecycle (the headline)

```
queued ──worker claim──▶ running ──▶ awaiting_approval ──approve──▶ committing ──▶ done
                                          │
                                          └──reject──▶ rejected (worktree torn down)
```

A **code task** (`type: assign-task`, `execution_path: code_task`):
1. `worktree.create` cuts an isolated worktree from `origin/<default>` on a fresh branch.
2. `agent_run.run_code_task` runs `claude -p` confined to that worktree (see the gate below).
3. `worktree.stage_and_diff` stages the edits and captures the diff — **no commit** — and the
   worker parks the job at `awaiting_approval`.
4. On `POST /approve`, the handler only sets the `committing` intent; the **worker** is the
   single writer that runs `worktree.commit` (feature branch, `--no-verify`, never pushes).

A **read-only job** (`trigger-review` / `send-directive` / `assign-analysis-task`) runs under
the read-only gate (no edits) and finishes `done` with a written result.

## The gate (`agent_run.py` + `control/job_*_gate*`)

Four independent layers, any one of which blocks the whole class of side effects:
1. **allow-list** flag — read + worktree-scoped edit only (no Bash/Task/WebFetch/MCP).
2. **`--permission-mode default`** (not bypass).
3. a **deny-by-default PreToolUse hook** that confines every read AND write to the worktree
   (`control/job_code_gate.json`, generated by `setup.sh` with this install's paths).
4. **empty `--mcp-config` + a credential-stripped child env** — no Snowflake/Slack/etc. handle
   exists in the job.

The agent never runs shell, commits, pushes, or merges. The trusted worker commits, and only
after a human approves.

## Paths & state

`parsers/paths.py` resolves everything from `STANDUP_ROOT` (default: the `standup/` dir that
contains this `portal/`; override via the env var). `WORKSPACE_ROOT` is its parent — dev folders
(`demo-app`, `standup/portal`) resolve under it. Machine-local runtime state lives in
`control/` (`jobs.db`, `runs/`, `requests/`, `results/`, `worktrees/`, `run.lock`,
`heartbeat.json`) and is all gitignored.

# Agent Team Harness — architecture

_Generated by `python .agentteam/bin/architecture.py` from the live harness. Do not edit by hand; the design rationale is in [DESIGN.md](DESIGN.md)._

**Software delivery, run by agents, governed by checks.** Seven teams take a story from request to deployment. Nothing advances because an agent said it was done.

| Teams | Agents | Phases | Gates | Checks | Human gates |
|---|---|---|---|---|---|
| 7 | 26 | 8 | 9 | 91 | 4 |

7 leads on `opus`, 19 ICs on `sonnet`.

## Structure

```
Supervisor (human) — owns the human gates
  └─ Claude (main session) — manages the leads laterally; produces nothing itself
       ├─ Product  pm-lead      → 2 ICs: pm-research, pm-spec
       ├─ UX       ux-lead      → 3 ICs: ux-flows, ux-states, ux-a11y
       ├─ Dev      dev-lead     → 2 ICs: dev-backend, dev-frontend
       ├─ QA       qa-lead      → 5 ICs: qa-unit, qa-integration, qa-system, qa-regression, qa-perf
       ├─ Review   review-lead  → 3 ICs: review-correctness, review-spec, review-security
       ├─ Visual   visual-lead  → 2 ICs: visual-capture, visual-judge
       ├─ DevOps   devops-lead  → 2 ICs: devops-build, devops-release
```

An IC reports to its lead, never past it, so a challenge is resolved inside the team that raised it.

QA writes test files only; dev may not write acceptance tests, snapshots or golden files (`**/tests/acceptance/**`, `**/test/acceptance/**`, `**/__snapshots__/**`, `**/golden/**`). The review team writes nothing — its ICs return findings and the lead records them through `story.py`.

## Human gates — decisions that are not Claude's to make

| Gate | After | Reviews |
|---|---|---|
| prd-signoff | g1-prd | `01-prd.md` |
| dev-plan-signoff | g3-plan | `03-dev/plan.md` |
| pre-merge | g5-review | `05-review/code-review.md` |
| deploy-beyond-dev | g7-deploy | `07-deploy/record.md` |

`story.py human-gate` needs an interactive terminal and a typed confirmation, and guard.py refuses it to every agent. Someone with shell access can still forge a record; that is the one place the design trusts the supervisor, and it is stated here rather than hidden.

## Enforcement — three layers, named honestly

| Layer | Mechanism | Failure looks like |
|---|---|---|
| Hard | `guard.py` PreToolUse hook | the tool call never runs |
| Audited | `gate.py`, 91 checks over artifacts on disk | the phase does not advance; failures listed |
| Instructed | `.claude/agents/*.md`, packets, the `/story` skill | nothing stops it — the weakest layer, never the only one |

guard.py fails open on an internal error so a guard bug can't brick a session, but every error is recorded and fails every gate of the phase it happened in.
Hard denies for every role: force-push, push-default-branch, delete-remote-branch, merge-pr, hook-bypass, destructive-rm, destructive-git, pipe-to-shell, disk-destroy, git-internals-write, secret paths, git internals, harness code, audit records, human-only commands, deploys beyond dev without the human gate.

## Operating it

| Command | What it does |
|---|---|
| `/add-project` | create, clone or adopt a project repo under `workspace/`, with its smoke suite verified |
| `/story <title>` | run a story through every phase, pausing at each human gate |
| `/architecture` | regenerate this document from the live harness |
| `python .agentteam/bin/selftest.py` | prove the gates still block; run it after touching anything under `.agentteam/` |
